# 输入连接检查优化：x.com 对照

仅合并一条 native input 命令内的连接检查，保留每条命令的归属检查、焦点开关、输入事件顺序和响应。开启焦点时准备连接一次，后续事件直接发送；失败不重新连接、不重放。下一条命令重新检查。

单元测试确认普通点击 tabs.get 从 5 次降到 2 次，普通按键从 4 次降到 2 次；组合键、type+Enter、拖拽复用本条命令连接。断连测试确认停止后续输入，保留焦点清理和主错误。

## 测量

执行顺序旧版→新版→旧版→新版，每轮重开已登录 x.com/home，用相同脚本运行 20 samples × 8 cases。所有用例检查实际效果及操作后的 visibilityState=hidden；不发帖。新版最后已重载到本机扩展。

8 cases：点击聚焦、Tab 默认行为、全选、退格、跨命令 Shift、移动/按下/松开、可信文字输入、移动后滚动。计时从 Unix socket 请求发出到完整响应收到，不含模型推理、CLI 启动、页面初次加载及用例准备/观察。均未开启 DevTools、计时钩子或逐 API 日志。

首轮旧版视口为 1920×1062 CSS，后续三轮为 1920×1118，均 DPR=2，搜索框坐标相同。这是 Chrome 调试提示条等界面状态可能带来的混杂；首轮不用于严格同环境提速结论。后续三轮记录的 viewport、DPR、visibility 和坐标完全一致。

## 结论与限制

四轮各160/160通过，调用与传输量完全相同。重复查询减少由单元测试直接证明。最终同视口的一组旧版→新版：中位耗时29.03→26.05 ms（下降10.3%），P95 98.79→85.97 ms；同环境较早的一轮新版中位25.69 ms，与新版复测接近。

现场结果不等于固定收益承诺。页面内容、网络和电脑负载不可固定；首轮还存在视口差异。不能把四轮均值或单次10.3%变化都归因于删除查询。确认优化掉冗余，不声称完全隔离了现场耗时的因果贡献。

本次未减少原生输入事件或焦点开关，因此之前从无效DOM模拟改为真实输入的主要成本仍在。先前逐API计时同时打开DevTools，观测扰动与页面/浏览器负载混杂，其占比和绝对时间不能当作正常运行的固定成本。网络抓取与输入并发，未隔离因果贡献。
